# Dodeca & Point

An exploratory mechanism experiment: twelve semantic advisers share one simulated body. Drive labels are a design analogy, not biological modules or evidence of consciousness.

- Run `npm ci`, then `npm test`. Runtime is Node 22+ and browser ES modules; Three.js is pinned in the lockfile.
- Start the offline lab with `npm start`; start with the existing scoped Proton credential using `./launch.ps1`. The key stays in the server process, never browser code or results.
- Run the frozen pilot with `./launch.ps1 -Pilot` after tests. Keep request/response receipts and hash the protocol, cases, and code before viewing results. Never overwrite a completed run.
- `config/pilot.json` and `preregister.md` define the finite comparison. This is an authored conflict-set feasibility pilot, not a general performance or consciousness claim.
- Use `frontend-quality` and browser validation for interface changes. Use `credentials-access` for authentication. Do not publish or deploy without a request.
- Deployment at `dodeca.alirezaafshan.com` and a separate GitHub repository are authorized in this task. Use `vps-operations` and the existing Deploy Manager; configure only this app additively.
- Locally the server listens on loopback. Docker listens on its internal interface and is published to a loopback-only host port. The provider bounds live calls per release, persists the budget across process restarts, rejects foreign origins, and never returns upstream error bodies.
- Source: https://docs.typesafe.ai/api (checked 2026-09-16). Use only synthetic simulation state. The twelve questions are independent calls to the same underlying model, not independently trained agents.
